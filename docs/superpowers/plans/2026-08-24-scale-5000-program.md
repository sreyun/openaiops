# 5000 台规模的逐模块提升计划（性能 / 安全 / 交互 / 配色）

> 起因：客户按「5000 台主机 + 几百个 HTTP/端口拨测 + 上万进程监控 + 日志监控」来问，
> 告警面在这个规模下是上万条。8 月 8 日的路线图
> （`specs/2026-08-08-scale-performance-roadmap-design.md`）按 ~200 台设计，
> 它的 Phase 2–4 方向正确但量级要重新校准。本文是那份路线图在 5000 台下的续篇，
> 也是"各方面逐模块彻底优化"这条要求的分期拆解——**一次做不完，必须分期，每期单独验证提交。**

规模假设（本文全部按这组数字算）：

| 资源 | 数量 |
|---|---|
| 主机 | 5000（30 秒上报 → 167 次/秒） |
| 当前告警 | 1–2 万条 |
| 拨测（http/tcp/udp/ping/dns） | 500 |
| 进程监控 | 10000 |
| 日志监控 | 若干关键主机 |
| 同时打开的控制台 | 10–20 |

容量口径见 `docs/CAPACITY.md`「二点五」。

## 第 1 期（本轮已做，2026-08-24）：热路径

目标：把「随主机数线性放大、且挂在上报/轮询路径上」的重复劳动去掉。全部是行为不变的改动。

| 位置 | 原来 | 现在 |
|---|---|---|
| `sre_api.go hostByID` | 每次 ListHosts 复制全部主机再线性找（40 个调用点，含每次上报的 `effectiveCategory`） | `store.GetHost` O(1) |
| `alerts.go Evaluate` | 每次调用对每台主机加一遍 2880 点的 1m 环（且在锁外读） | 1m 层追加时预算 `procBase1h`（最近 60 点） |
| `check.go sweep` | 单协程**串行**跑所有拨测，一个不通目标堵住整队 | 网络类走 `AIOPS_CHECK_WORKERS`（32）并发 + inflight 守卫；进程检查就地执行 |
| `check.go probeProcess` | 每个进程名 `ToLower` 分配一次（1 万监控 × 256 名 / 5 秒） | 零分配折叠匹配 `containsSubstrFold` |
| `check.go checkHistMax` | 常量 2880 | `AIOPS_CHECK_HIST_MAX` 可调 |
| `vm.go enqueueCheck` | 队列满静默丢 | 计数 + `aiops_vm_dropped_check_samples_total` |
| `push.go pushPush` | 每个 WebSocket 连接每 3 秒各算一遍全量摘要 | 2 秒 TTL 的共享快照 |
| `host_rbac.go` | 每台主机 / 每条告警复制一次整张 folder 映射并展开子树 | `hostAccessFor(u)` 每请求算一次 |
| `host_folders.go ensureHostFoldersMigrated` | 每次 GET /hosts 拿写锁 | 读锁快路径 |
| `display_redact.go` | 每条活动日志重排全部主机 ID 并 ListHosts 线性找 | 每请求一个 redactor |
| `topology.go` | 边循环里反复 ListHosts × effectiveCategory | 每请求一份分类快照 |
| `handlers.go /app.js` | 每次请求从 embed 复制 38 个模块拼接 | 拼一次 + ETag/304 |
| `notify.go` | 每次发送编译正则 / 解析 webhook 模板 | 包级正则 + 模板缓存 |
| `logstore.go count/errorCount` | 只读却拿写锁 | 读锁 |
| `cmd/agent` 进程名上限 | 256（静默截断 → 进程监控误报） | 1024 |
| 经典版 `hardware.js` | 逐台 `/hardware/health`（Vue 版上一轮已改） | 一次批量 |
| 经典版告警面 / 拨测面 | 全量进 DOM | 客户端切页（100 / 60） |
| Vue 版 6 张表 | 全量进 DOM | `pageSlice/clampPage` 切页；关键字去抖 |
| Vue 版 `resolveHostLabel` | 单元格模板里对主机数组线性 find | WeakMap 索引 |
| Vue 版 `useHostLabels` | 名叫 lite、实际拉整份 `/hosts` | `/hosts/meta`（现在带 IP） |

## 第 2 期：服务端分页契约（上万条告警的地基）

现在两个控制台都只**渲染**一页，但 `/alerts`、`/checks`、`/activity`、`/events`、`/hosts`
仍然整份返回：上万条告警 × 每 5 秒 × 每个控制台。沿用 8 月 8 日路线图的契约
（`limit` 默认 50 / 上限 200、`offset`、`total`、服务端筛选），按以下顺序落地：

1. `GET /api/v1/alerts`：`limit/offset/level/status/type/host/q`，响应体保持数组
   （经典版 `Array.isArray`），总数走 `X-Total-Count`；另加 `GET /alerts/summary`
   （按级别/类型/主机 Top N 的计数）给概览与导航角标用，角标不该靠拉全量来数。
2. `GET /api/v1/checks`：同款；`DownAlerts()` 改成锁内拍快照、锁外算阈值。
3. `GET /api/v1/activity` / `events`：`limit/offset/host/kind/since`。
4. `GET /api/v1/hosts`：列表页改用 `/hosts/meta` + 按需 `latest`；只有主机页与概览
   TOP 榜需要指标，前者分页取、后者服务端算 Top N。
5. WebSocket 推送改为摘要（计数 + 变化的告警 key），不再每 3 秒广播全量告警。

验收：5000 台 / 1 万告警下，一个控制台每秒出口 < 50 KB；十个控制台服务端 CPU 增量 < 1 核。
两个控制台都要过（路线图 A 方案）。

## 第 3 期：内存模型

- 历史环按**总预算**自动定深（`AIOPS_HIST_BUDGET_MB`，启动与主机数变化时重算），
  而不是要求运维手算三个变量；`hist5m` 层在 VM 可用时改为惰性（只有 VM 读失败回退时才积累）。
- 拨测历史环：进程类只在状态变化时记点（它的"延迟"没有意义）；网络类保留。
- `logstore` 按主机配额（例如每台最多占环的 2%），话痨主机不能把其余主机挤出去；
  `searchPage` 与 `searchStats` 合并成一次扫描。
- `store.go` 每条事件 / 审计 `go pg.append…` 无上限起协程 → 有界队列 + 背压计数。
- `pgstore.go saveIncidents/saveTickets` 未变更时不开事务。

验收：5000 台空跑 24 小时 RSS 稳定；`aiops_pg_flush_duration_seconds` < 1 s。

## 第 4 期：SLO / 查询侧

- `slo.go` 每个 SLO 每次评估 5 次 VM 查询 + 3 MB 分配（`GetHistory` 在读锁下）：
  结果按评估周期缓存；`/slos`、状态页、值班报告读缓存不重算。
- `store.GetHistory` 改为锁内只切片、锁外过滤。
- `agent_update.go recordSkip` 上限淘汰 O(n) → 最小堆或时间桶。

---

## 第 5 期：安全（规模本身带来的面）

- 新增的聚合/分页端点逐个过主机级 RBAC（本轮 `hostAccessFor` 已是统一入口），
  用 `scripts/` 的 RBAC 扫描脚本核对。
- 限流：`apiRateMaxAuthPerUser` 1800/分钟在 20 个控制台 × 5 秒轮询 × 5 个接口时会误伤，
  改成按接口分桶（列表类 / 写操作类 / 流式类）。
- 审计链在上万告警确认/静默的批量操作下的吞吐（咨询锁串行追加）：批量操作合并成一条审计。
- 会话与 CSRF 在多控制台并发下的行为复核；`LimitNOFILE` 写进 systemd 单元与 compose。

## 第 6 期：交互与配色（在数据层撑住之后才有意义）

- 万行级表格用 `el-table-v2` 虚拟滚动替代切页（告警、拨测、主机安全摘要三处优先）；
  主机选择器（`SreView` 6 处 × 5000 项 `el-option`）换 `el-select-v2`。
- 告警面在上万条下的分诊交互：按主机 / 类型 / 分组折叠聚合、批量确认与静默、
  "只看新增"视图；概览的告警角标显示"严重 N · 警告 M"而不是一个总数。
- 配色：延续 8 月 22 日 v2 打磨计划里留下的三处品牌色决策；状态标签在高密度列表里的对比度
  走同一套刻度令牌；暗色主题下万行表格的斑马纹与选中态复核。
- 经典版：拨测面卡片视图在上万项下默认切到列表视图；告警面加"按主机折叠"。

## 验证手段（每期都要过）

- 远端构建机上的 `gogate.sh` + `gate.sh`（等价于 CI 门禁）。
- 压测：`scripts/` 下补一个"假 Agent"发生器（N 台 × 30 秒上报 + 终端/桌面 wait 长轮询），
  跑 5000 台 30 分钟，看 `/metrics` 里的 `aiops_pg_flush_duration_seconds`、
  `aiops_vm_dropped_samples_total`、`aiops_vm_dropped_check_samples_total`、goroutine 数、RSS。
- 前端：Playwright 套件（sweep / layout / contrast）跑在灌了 5000 台假数据的实例上。
