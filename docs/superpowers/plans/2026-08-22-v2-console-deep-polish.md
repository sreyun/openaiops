# 新版控制台的一轮深度打磨：能排序、看得见时间、读得清字

这一轮不修某个坏掉的功能，修的是**一直没做**的那几件事。起点是拿远端那套 Playwright
验收套件（`/root/uicheck`）把 23 条路由在 1440 / 390 两个宽度、浅/深两套主题、三种语言下
各扫一遍，再把结果和源码对照。爬虫本身几乎没报错——新前端的"能跑"这一层是干净的；
问题都在下一层。

## 一、90 张表，一张都不能点列头排序

`grep -c sortable frontend/src/views/*.vue` 的结果是 0。主机页有一个 5 项固定排序的下拉框
（方向也写死），其余 22 个视图一律"后端给什么顺序就看什么顺序"。

对着一个监控台，"按 CPU 从高到低看谁要炸""按最近告警时间排""哪台机器高危漏洞最多"
是最高频的三个动作，此前都得靠人眼一行行扫。

### 为什么不能直接写 `sortable`

这些表几乎都是 `:data="pagedRows"`——已经切过页的那一页。Element Plus 内置排序只对传进去
的数组排序，于是"按 CPU 降序"的实际含义变成"**在第 1 页的 50 台里**降序"，第 2 页可能还有
更高的。这种错比不能排序更糟：它看起来像在工作。

所以统一走 `sortable="custom"` + `composables/useTableSort.ts`：排序状态在视图里，
对**过滤后的全集**排完再交给分页切片。三条刻意的取舍写在文件注释里：

- **空值永远垫底**，与方向无关——降序时把一堆「—」顶到第一屏，等于把真正要看的行挤下去；
- **稳定排序**（复制一份再 `sort`），值相同的行保持数据源原始顺序，等于免费拿到一个合理的次级键；
- **区域感知比较**复用 `shared/collator.ts`，`web-10` 排在 `web-9` 后面、`10.0.0.10` 排在 `10.0.0.9` 后面。

级别、严重度这类列按**权重**排而不是按字面：按字面排会得到 `critical < high < info < low <
medium`，正好把最该先看的一条塞到中间。

覆盖到的表（每个视图的主表）：主机、告警（当前 + 历史）、事件、资源（硬件 / 虚机）、
拨测、API 监控（事务 / SLA）、安全（扫描历史 / 主机汇总 / Web 漏洞 / 主机漏洞）、
流水线、自动化（剧本 / 执行）、抓取、数据源、网络（连接 / 接口）。

**刻意没做**的是 K8s 的 Pod / Deployment 表和资源页的容器表：它们走**服务端游标分页**，
客户端排序只能排当前这一页，正是上面那个"看起来像在工作"的陷阱。要做得由服务端出排序参数。

### 顺带补上的一处：告警页「当前告警」原来根本没有分页

上面那套"排全集再切片"落到告警页时才发现，这张表压根没切片——`:data="rows"`，接口不设
上限，活跃告警的条数是「主机数 × 阈值条数」。几百台机器一起抖一下就是几千行一次性画进
DOM，排序也跟着一起慢。现在和别的表一样按 50 条切页；筛选条件一变回第 1 页，删到只剩两
页时也不会把人留在第 5 页看空白。

勾选用 `row-key` + `reserve-selection` 跨页保留——批量确认按钮上的 `(n)` 得是全部勾选数，
不是"本页勾选数"，否则翻个页再点确认，少确认的那些是静默丢的。

主机页还有一处：它的表头排序和卡片视图共用同一个下拉框，而 el-table 点第三次是"取消
排序"。取消后卡片视图没有表头可看、下拉框也没东西可显示，所以这一页把"取消"接成回落到
默认的 IP 升序，两个视图始终是同一个顺序。

## 二、看不见的时间

三处接口里有、界面上一个字都没有的信息：

| 位置 | 缺什么 | 后果 |
|---|---|---|
| 告警页「当前告警」 | `since`（首次触发） | 看不出这条是 3 分钟前炸的还是挂了 3 天；导出的 CSV 里也没有 |
| 自动化页「执行记录」 | `start_time` / `end_time` | 一屏记录看不出哪条是刚才跑的、哪条跑了半小时 |
| 安全页「主机扫描结果」 | `severity` | 200 条发现里哪条要紧，全靠自己读标题 |

告警那条尤其说明问题：**经典控制台一直在告警行上显示「持续 X」并把首次触发时间挂在
title 上**（`web/js/overview.js`），新前端漏了这一列。`check:parity` 只审接口调用，
审不到"这个接口的这个字段有没有被显示"，所以一路绿灯。

现在告警表有一列「持续」（可排序，hover 显示首次触发时间，30 秒自己走字），导出多两列；
执行记录多「开始时间」「耗时」两列；主机漏洞多一列带配色的「严重度」，并默认按它倒序——
打开那个抽屉本来就是为了知道"先修哪个"。

## 三、一个控制台，三种时间

`shared/format.ts` 的 `formatDateTime` 注释写着"与经典控制台一致"，实际按**浏览器本地时钟**
渲染；而视图里另有 **14 处**各自 `toLocaleString("zh-CN", { timeZone: "Asia/Shanghai", … })`
的复制品——它们钉对了时区，却因为 zh-CN 的习惯输出 `2026/08/21 19:00:00`（斜杠）。
经典版是北京时间 + 短横线。于是同一个控制台里同时存在三种时间格式，其中一种对非 CST 用户
还会差好几个小时。

北京时间是**产品决定**（`web/js/core.js` 的注释原话是 "Product clock … independent of
browser TZ"），不是 bug。这轮把 `formatDateTime` 改成那一种，14 处复制品全部改调它，
`format.spec.ts` 用固定 UTC 时间戳钉住"不随测试机时区变化"。

## 四、账号读不出来时，控制台会悄悄退化成只读

`/me` 失败（后端重启、反代 502、网络抖动）时，`stores/auth.ts` 只 `console.warn` 一行：
`user` 变 null → `isAdmin` / `canOperate` 全线 false → **所有写操作按钮凭空消失**，
界面上没有任何一句话解释。故障注入验收（所有 GET 打成 500）在设置页报的
"没有任何错误态提示"就是这个的一个侧面。

现在 store 留下 `bootError`（401 除外——那是没登录，归路由守卫管），外壳在
offline / 推送降级同一排位置显示一条带重试的条幅。四条单元测试钉住这个性质，
包括"重试成功后条幅要消失"。

## 五、13 个标签页，一个都进不了链接

`useTabQuery` 这个 composable 已经存在，注释里写着"带标签页的 16 个视图里只有 8 个同步了
`?tab=`"。这轮补上 **SRE 中枢**（13 个外层标签 + AI 资产的 3 个内层，用 `aiTab` 键）与
**CI/CD**。

SRE 原先有一个**单向**的 `route.query.tab` 监听——能读不能写，切标签不进 URL。改成
`useTabQuery` 双向同步，原来那条"只读用户不能进 AI 助手页"的兜底保留为独立 watcher：
链接是转手传的，发链接的人有权限不代表点的人有。（「AI 助手」那个 pane 是
`v-if="canOperate"`，少了这条兜底，只读用户点开链接看到的是一片空白而不是一句解释。）

**安全中心（10 个）和设置（11 个）特意没换。** 它们本来就是双向同步的，而且各自多一层
通用 composable 装不下的逻辑：安全中心有一张 `TAB_ALIASES`（`host-security` / `web-security`
这类旧链接还在别人的收藏夹里），设置页按角色收敛可见标签（只读用户拿到 `?tab=users`
要落回「账号」而不是一个空 pane）。换成 `useTabQuery` 等于把这两件事丢掉，不值。

## 六、对比度：状态标签是全站密度最高的元素

浅色主题下 Element Plus 拿 `--el-color-*` 当浅底上的**文字色**用，实测：

```
成功 #00b42a on #f0f9eb = 2.57:1     信息 #3491fa on #f4f4f5 = 2.91:1
警告 #d97706 on #fdf6ec = 2.97:1     危险 #f53f3f on #fef0f0 = 3.34:1
```

全部低于 AA 的 4.5:1。仓库里早有人为**文字型按钮**做过这件事（`main.css` 那段注释），
只是没延伸到标签、描边按钮和角标——而标签是一屏几十个的东西。

改法沿用同一套：换成设计系统里已备好的 `--aiops-*-txt`（文字专用、压深一档），
色相不变，4.65～4.92:1。实心标签（白字压鲜艳底）浅色下把底色换成同一批 txt 色；
深色主题下反过来——白字在 `#f0a33a` 上只有 2.1:1，换成近黑字是 8.8:1，这也是深色控制台
里通行的做法。

一个中途踩到的坑记在 CSS 注释里：`:not(.el-tag--dark)` 不能省，否则实心标签的白字会被
一起改成 txt 色，和刚换的底色变成同一个颜色——**直接看不见**。验收脚本当场报了
`1:1 (需 4.5)`。

同一套解法后来又按验收报告补了三类：

- **实心的语义按钮**（`el-button--success/warning/danger/info`，白字压鲜艳底）：浅色下
  「AI 整体研判」是 2.78:1，深色下更低——1.97:1。浅色换底、深色换近黑字，和实心标签一致；
- **`el-alert`**（浅底 + 语义色文字）：警告 2.97:1、信息 2.91:1，标题和描述都从根节点继承，
  改一处就够；
- **浅色主题的 placeholder**（Element Plus 默认 `#a8abb2`，白底 2.3:1）：这个控制台里的
  placeholder 常常不是提示语而是**当前状态**——筛选下拉不选就显示「全部主机」「全部级别」，
  那是这一屏正在看什么的唯一说明，不该比正文难读一倍。改用 `--aiops-muted`（5.08:1）。

实测结果：每页 10～18 处违规降到 1～4 处，剩下的**全部**是下面这两个品牌色。

### 留下来的三处，是品牌色决定，不该由这轮代改

| 元素 | 现状 | 达标需要 |
|---|---|---|
| 「安装 Agent」按钮（品牌橙 `#ff6a00` 白字） | 2.87:1 | 橙色压到 `#d24500` 一档 |
| 主色按钮 / 单选按钮 / 选中的标签页（浅色 `#1677ff`） | 4.1:1 | 蓝色压到 `#0a63e0`（设计系统里已备好，就是 `--aiops-accent-txt`） |
| 同上（深色 `#3b8bff` 白字） | 3.32:1 | 同样压深 |

都只差一档，但改的是品牌主色本身，影响整个产品的观感，交给产品侧定。

## 七、门禁盲区：模板里的中文一直漏得出去

`check:hardcoded-copy` 里有一段 `templateTextFindings`，本意就是抓 Vue 模板里的裸中文。
它用 `/<template[^>]*>([\s\S]*?)<\/template>/` 非贪婪匹配根模板——于是遇到第一个具名插槽的
`</template>` 就收工。一个 1200 行的视图实际只扫了开头几十行。

结果是四处中文一路绿灯放到线上：

```
AiSettingsView.vue:1214   {{ t('aiSettings.tabUsage') }} · 历史趋势
HostsView.vue:1519        {{ g.hosts?.length || 0 }} 条 · 可清理 {{ g.stale || 0 }}
SecurityView.vue:2280     {{ caEvent.redaction_count }} 处
SqlView.vue:1820          清除全部历史
```

四处都改成了 `t()`（三语齐备），门禁本身改成按行首定位根模板首尾，并顺手补了第二类
漏网之鱼：**静态属性值**（`placeholder="请输入"`）——去标签那一步会把它和标签一起抹掉。
把这四处还原成改前的样子，新门禁准确报出 4 条。

## 八、怎么验的

- 单元：`useTableSort.spec.ts`（11 条，含"空值垫底""稳定排序""不改原数组""第三次点击清除排序"）、
  `auth.spec.ts`（4 条）、`AlertsView.paging.mount.spec.ts`（挂真表：120 条只画 50 行、
  翻页勾选不掉、最后一页 20 条）、`format.spec.ts` 补 3 条产品时钟断言。全量 200 → 219 条。
- 类型 / lint / 15 条自定义门禁：远端全绿。
- 浏览器（远端真服务 + 真 Agent，`uicheck/v2sort.mjs` 与 `v2sort3.mjs`）：点主机表 CPU 列头 →
  升序 `[0,0,0,4]`、降序 `[4,0,0,0]`、表头箭头状态跟随，第三次点击（取消）落回 IP 升序且
  空 IP 垫底；告警「持续」列渲染出 `59s`；`/v2/#/sre?tab=slo` 落在 SLO 页，切标签后 URL
  变成 `?tab=assist`；`/v2/#/settings?tab=users` 落在用户页；两轮都是 0 条控制台报错。
- 版式 / 故障注入 / 三语残留 / 对比度：`verify-all.sh` 全套复跑。

## 九、这轮没碰、但看见了的

- **服务端产出的中文在英文界面里原样显示**：告警消息、活动日志、健康检查项名、
  情报源目录（`Nuclei 模板库` 等）、AI 建议提示词（`sreyun_suggest.go`）、
  `未找到 pg_dump，请安装…`。这些不是前端能修的，要服务端按请求语言产出，是独立一轮的事。
- **K8s / 容器表的服务端排序**：见第一节末尾。
- **`.cell el-tooltip` 的"截断无 title"**：验收脚本按 `title` 属性判定，而 Element Plus 的
  `show-overflow-tooltip` 用的是浮层不是 title——那一大片报告是误报，无需处理。
- **`.el-row 超出父容器 6px`**：Element Plus gutter 的负 margin，被 `.main` 的 padding 吃掉了。
  实测 390px 下 `document.scrollWidth == clientWidth`，没有横向滚动，同样是误报。
